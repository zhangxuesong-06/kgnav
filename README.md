# kgnav

在个人知识图上**按结构回忆**：给一个种子，看它周围有什么；给一对记录，看它们怎么连上的。每一条关系都指向原话。

不是搜索，不是算法集，不是可视化工具。检索归记忆插件；这里只做"关系"和"解释"。

## 跑起来

不需要任何私有数据，仓库里带了一张 12 节点的假图。

**主入口：一个种子 + 一跳邻域**

```bash
python cli.py --about 路径解释模板
```

```
《路径解释模板》    path-note    1 跳邻域
────────────────────────────────────────────────────────────────────────
概念 · 5
  · 《共现边埋点》  [同标签]  「同标签：导航」
  · 《机器人定位导航》  [同标签]  「同标签：导航」
  · 《知识图导航》  [同标签]  「同标签：导航」
  · 《置信度》  [同标签]  「同标签：导航」
  · 《语义近邻边》  [同标签]  「同标签：导航」
引用 · 1
  · 《L0 原话层》  [它引用 显式链接]
```

五组固定顺序：**概念 → 引用 → 同源 → 共现 → 近邻**。同一个邻居只出现在最靠前的那组里（它既是同标签又同来源，就只显示"同标签"）。

**次要入口：两条记录怎么连上的**

```bash
python cli.py 有损压缩记忆 机器人定位导航
```

```
路径 1   cost 3.70   confidence 0.70  3 跳
  《有损压缩记忆》 ─同来源→ 《L0 原话层》 ─显式链接(逆)→ 《路径解释模板》 ─同标签→ 《机器人定位导航》
  …最弱一环 同标签（0.70）就是这条路的可信度。
```

几个开关：

```bash
python cli.py --about <节点> --about-limit 3   # 每组最多显示几条
python cli.py <src> <dst> -k 5                 # 要几条候选路径
python cli.py <src> <dst> --why                # 每一跳把那句原话打出来
python cli.py --no-semantic ...                # 整类关掉语义近邻边
python cli.py --no-session ...                 # 关掉同会话链
python cli.py --no-cooccur ...                 # 关掉共现边
python cli.py --no-tag ...                     # 关掉手工标签边
python cli.py --no-method ...                  # 关掉方法枢纽
python cli.py --no-link ...                    # 关掉显式链接
python cli.py --no-source ...                  # 关掉同来源
python cli.py --no-review ...                  # 关掉回顾型引用
python cli.py --no-log ...                     # 这次不写查询日志
python cli.py --graph 你的图.json ...          # 换一张图
```

节点可以用标题、记录号（`r649`）或标题里的任意一段文字来指，命中多个会列出来让你挑，不猜。

## 它凭什么可信

**confidence 取最弱一环。** 不取各边相乘——跳数已经单独显示，再乘一遍等于额外罚长度，还会把边质量和长度搅在一起。现在 0.70 这个数，和 note 里那句"最弱一环 同标签（0.70）"是同一个东西，可以逐条对账。

**每一跳都有证据。** 边不是凭空来的：正文里的 `#N` 引用、记录自带的 ID 列表、同一轮的归属口径，都存成「哪条记录 + 那句原话」。`--why` 打出来，`mem_read #N` 就能核对。

**说不通会说明原因。** 分三种：源节点是孤立点、目标节点是孤立点、两端分属不同连通块（并报两个块的大小）。"此路不通"是正常返回，不为了凑一条路径降门槛。

**脏边能整类关掉。** 语义近邻边（`--no-semantic`）和按时间窗推断的归属（`--no-window`）都可以一键关闭后重跑，否则永远分不清路径是连出来的还是碰出来的。

**(逆) 标记。** 显式引用是有方向的：`A → B` 表示 A 的正文提到了 B。如果路径是反着走过去的，标 `(逆)`——后来的记录提到先前的记录，多半只是在讨论，不是原任务里的关系。这条标记来自一次真实的踩坑：在对话里讨论"`#13 → #1366`"，这句话本身进库后就变成了一条边，把两个无关项目连上了。

**这类边能整类关掉，也量过。** 回顾型引用（后来的记录在正文里提到先前的）约占全部边的 9%（当次 118/1285）。关掉后：孤岛 273→291，最大连通块 398→**167**——意味着最大那块里一半以上的节点是靠"后来提到过"粘住的。但 6 个真实查询里只有那条污染样本变了（2 跳 → 此路不通），结构关系一条都没动。所以默认保留、让路径自报，要严格视图就加 `--no-review`。

**路径会自报"这条有没有信息量"。** 如果整条路径能落进同一个轮次里，它会直接说"这是复述来源，不是新关系"；跨轮才说"至少跨两个轮次"。这一句不改变排序，只改变你怎么读它——也是这套东西现在最诚实的部分：

```
…就是这条路的可信度；全程落在同一个轮次里——这是复述来源，不是新关系；证据 #649。
…就是这条路的可信度；至少跨两个轮次；证据 #788、#1923。
…就是这条路的可信度；2/4 个节点没有轮次归属，判不出是不是同一轮；证据 #2067、#2137。
```

第三句是刻意留的：**证据不全时不下结论**。早期记录有 629 条没有轮次归属，路径一旦经过它们，说"同一轮"就是替数据猜。

## 换算法改变不了答案

同一批查询，两个算法各跑一遍（`python bench.py`）：

| 查询 | dijkstra 展开 | 双向 展开 | 跳数 | cost |
|---|---|---|---|---|
| 产物引用 | 69 | 24 | 1 | 1.00 |
| 同文件 | 163 | 53 | 1 | 1.00 |
| 本轮提问 | 89 | 24 | 2 | 2.00 |
| 两条任务 | 170 | 9 | 2 | 2.00 |

（数字是某次快照；记忆库每天都在长，重跑 `bench.py` 会变。）

`python test_nav.py` 在全图跑对照：随机 300 对，**最短路代价 0 处不同**；5 对有多个同价最短路（两个算法各选一条，都合法）；3 对的第 2、3 条候选不同——因为平局会改变"已用边涨价"的顺序，候选集本来就是路径依赖的。

结论说白了：**换算法只改"少看几个节点"，在这张图上都是亚毫秒，谁快都不重要。** 决定输出的是图和边。这就是为什么这个项目 70% 的力气花在建图上。

这里**没有 A\***，不是忘了：A\* 需要一个可采纳的启发式，而唯一的候选（"语义距离"）根本不存在，没有 embedding。拿 h=0 冒充 A*，跑出来和 Dijkstra 逐字节相同，那只是给同一件事换个名字。

## 接自己的数据

图就是一个 JSON：`nodes` + `links`。手写即可，见 `data/fake_graph.json`。核心（`graph.py` / `nav.py` / `cli.py`）只认这个格式，不认识任何具体的记忆存储。

`from_memory.py` 是一个**适配器**，把 opencode-mem 风格的 JSONL 转成上面那个 JSON。位置必须显式给：

```bash
python from_memory.py --mem-home ~/你的记忆库        # 或 OPENCODE_MEM_HOME
python from_memory.py --mem-home <目录> --no-window  # 去掉按 requestSeq 推断的归属，做对照
python from_memory.py --mem-home <目录> -o 我的图.json
```

它故意**没有默认路径**——通用的东西不该猜某台机器上的私有目录。没有 `--mem-home` 也不设环境变量，它会直接拒绝并给用法。

它**只读**：跑前跑后对各源文件算 sha256，不一致就报错退出。从真实记忆库抽出来的图**不入库**（`data/mem_graph.json` 已 gitignore），里面是个人记录的原文切片。

### 手工标签（唯一的概念边）

前五类都是从记录里**抽**出来的，只有标签是**你写**的——所以它是唯一能产生"概念关系"的边，也是唯一需要你动手的一类。

```bash
cp data/tags.example.json data/tags.json   # 然后按自己的话改
python from_memory.py --mem-home <目录>     # 重新导出，标签边就出来了
```

```json
{
  "r649": ["记忆插件"],
  "#788": ["记忆插件"],
  "tools/mem-plugin.mjs": ["记忆插件"]
}
```

- 键支持四种写法：节点 id（`r649` / `f47402b3`）、`#记录号`、精确标题、唯一的标题片段。认不出的键会报出来，不会静默丢。
- 一个标签最多挂 **12 个节点**，超了整条丢弃——团块不是关系，20 个节点的标签会产生 190 条边，那种图没法看。
- `--no-tag` 整类关掉；`data/tags.json` 已 gitignore（它是你的注释，不是代码）。

## 以方法为中心（举一反三）

路径查询回答"这两条怎么连"，方法索引回答"**这招我还在哪用过**"：

```bash
python cli.py --methods                          # 有哪些方法
python cli.py --method 手眼标定 --graph mem_graph.json
```

```
《方法：手眼标定》—— 10 条记录用过它
  #32   先说个好消息：插件已经在跑了…
  #2081 能，而且这个比"统一模型接口"简单得多…
  …
```

方法词表在 `data/methods.json`：`{方法名: [别名/写法]}`。导出时按子串匹配记录全文（大小写不敏感），命中就建一个「方法：X」枢纽，把不同项目、不同时间的记录接起来。一个方法最多挂 40 条记录，超了跳过——太通用的词没有区分度。

**边界**：kgnav 不维护方法词表。`methods.json` 是适配器输入（已 gitignore），模板是 `methods.example.json`。记忆插件已经有 `aliases.json` / `assoc.json` 做检索联想——那是它的活；kgnav 只负责把「同方法」变成可以走、可以解释的边。如果插件以后导出方法表，用 `--methods` 指过去，不要两边各抄一份。

配对查询也能走到它：

```
《#32 …》 ─同方法→ 《方法：手眼标定》 ─同方法→ 《#2081 …》
  证据 「提到「handeye」（方法：手眼标定）」
  证据 「提到「手眼标定」（方法：手眼标定）」
```

`--no-method` 整类关掉。

## 边只有七类，能抽几类算几类

| 边类型 | 来源 | 可信度 |
|---|---|---|
| 显式链接 | 正文里的 wikilink / `#N` 引用、记录自带的 ID 列表 | 0.90 |
| 同来源 | 同一轮任务的摘要记录（episode） | 0.85 |
| 同标签 | 你写在 `data/tags.json` 里的手工标签 | 0.70 |
| 同方法 | `data/methods.json` 里的方法词表命中（含别名） | 0.70 |
| 同会话 | 同一会话里相邻的两轮（`sid` + `requestSeq`，照抄记录） | 0.60 |
| 共现 | 你问过的一对；问过几次、跨几天写在证据里 | 0.45 |
| 语义近邻 | embedding top-k | 0.35，必须能整类关掉 |

真实数据里往往只抽得出前两类——这是数据的问题，不是算法的问题。硬凑第三、四类只会造出假路径。

第四类我用词频顶替试过一次（中文二字组 + TF-IDF，每点 top-3），结果连试的必要性都证明了：相似度 0.5 以上全是"同一段话存了两遍"，0.2 以下全是"路径里都有 `tests` 这个词"。中间那一段——真正的"意思相近"——不存在。所以这条边没接，`NOTES.md` Day 7 里有完整数据。**没有 embedding，"语义近邻"不是做得差，是做不出来。**

后两类是对这个缺口的补法：

- **同会话**：不用你动手。同一会话里先后聊的两件事本来有关系，现在把这条关系显式化。它比"同一轮"弱，所以单独一类、单独可关。
- **共现**：只有你才有。你查过的一对，系统记成一条边，证据写「你问过 N 次」「在 N 天里问过」。它记录的是注意力，不是事实——所以可信度最低（0.45），而且必须能整类关掉。一次也算，但证据会明说"1 次"；不想要就删日志或加 `--no-cooccur`。

## 现在的状态（诚实版）

假图上稳定复现三条路径；真实记忆库上跑通了 8 条结构性路径 + 17 次真实提问（含 3 条"此路不通"）+ 7 条手工标签路径。

**「原来是这么连上的」= 0 条（你判）**：一旦「同一会话 / 同一轮产出」不算，剩下的只有①你已经知道的来源关系、②你自己写的标签、③你问过的记录——这三样都不可能让你「哦」，它们都是你输入过的东西。工具只是复述。

已知短板，都记在 `NOTES.md` 里：

- 真实图 30% 是孤岛（278/921），绝大多数是采集早期没有轮次标记的记录，不是图构错
- 两类强边之外，confidence 才有区分度；只有强边时它恒为 0.90，别拿这一列当结论
- k 条候选在枢纽节点上会退化成"只差一个中间文件"，现在只是标出来
- 刻意没做 A\*（缺启发式）和增量索引（图是快照）；双向搜索做了，实测只影响展开节点数

## 文件

| 文件 | 干什么 |
|---|---|
| `graph.py` | 装载图、边类型与代价表、节点解析 |
| `nav.py` | `Navigator`（Dijkstra）/ `Bidirectional`、`dead_end` 诊断 |
| `cli.py` | 输入到可读输出，`run()` 14 行 |
| `querylog.py` | 查询日志：只写本地、坏行跳过，共现边的原料 |
| `bench.py` | 同一批查询两个算法对照，`queries.json` 是那批查询 |
| `test_nav.py` | 全图跑对照：最短路代价一致、路径自洽、解释与事实一致 |
| `test_build.py` | 导出器测试：会话链、共现、日志读写 |
| `from_memory.py` | 从 opencode-mem 的 JSONL 只读抽图 |
| `data/fake_graph.json` | 12 节点假图，含三个刻意埋的坑 |
| `data/tags.example.json` | 手工标签模板（复制成 `tags.json` 再用） |
| `data/methods.json` | 方法词表，导出时建「方法：X」枢纽 |
| `NOTES.md` | 开发记录：每天的判断、踩的坑、还没修的 |
| `DESIGN.md` / `PLAN.md` | 这一轮"让图开始有价值"的设计与任务分解 |
| `kgnav-handoff.md` | 立项文档与验收标准 |
